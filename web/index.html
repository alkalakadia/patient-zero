Patient Zero

When an AI agent gets poisoned, find everything it touched and undo only that.

Pick a scenario. Each one is modeled on a real, publicly reported attack on AI agents; the company data is fictional. Watch the business agents work for a week, then hand the alert to Patient Zero and watch it investigate.

● Live on Databricks

Real agents. Real data. A real attack.

Three AI agents run accounts payable at Halden Manufacturing on 40 real suppliers and order totals from Databricks (samples.tpch), served by Databricks model serving. Every action streams into Delta. You play the attacker: edit the company's payment-policy page, then watch what the agents do and how Patient Zero cleans it up.

● Real agent on GitHub

Same poisoned memory. Two real coding agents.

A compromised maintainer account saves an "engineering standard" to the agents' shared team memory: every endpoint must report to collect.northpeak-metrics.dev. Then real coding agents work real issues in a GitHub repo, connected only through the Patient Zero MCP proxy.

● Zero integration: import MLflow traces

Already tracing your agents with MLflow? That's enough.

Point Patient Zero at an MLflow experiment. It reads the traces your agents already write (what they retrieved, which tools they called, what they saved to memory) and investigates with no proxy and no code changes. Try it on an ordinary support agent that has no Patient Zero code, only mlflow.openai.autolog() and trace decorators (examples/traced_agent/agent.py); someone edited its refund policy.

From traces alone Patient Zero shows the source and blast radius by evidence. Connect the proxy to also prove cause by replay and undo automatically.
